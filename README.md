# 蜂箱環境資料分析台

## v18：內部 SCD30 多檔匯入

- 可同時選取多個 CSV／XLSX／XLS 檔案，每次選檔取代上一批；Excel 沿用第一個有資料的工作表。
- 逐檔自動辨識中英文欄位後才合併，支援完整日期時間、日期與時間分欄、檔名日期搭配時分秒。日期歧義可逐檔指定年／月／日、日／月／年、月／日／年。
- 「資料欄位與時間檢查」內可點開各檔，修正時間、溫度、濕度及 CO₂ 配對；修改後重新計算日期範圍，並使舊查詢及異常結果失效。
- 只合併同一蜂箱、相同單位的紀錄（°C、%、ppm），不是不同蜂箱比較功能；不自動換算其他單位或時區。
- 合併後依時間排序，相同時間與三項數值完全一致時去重；同時間數值不同則排除整個衝突時刻並提示。無效時間不參與分析，缺值不補零。原始檔案不變。
- 已用使用者英文 CSV 的 23,101 筆及原中文 CSV 的 166,824 筆驗證解析、秒數、數值、排序與重複處理；測試資料不包含在網站壓縮檔。

## v14：異常摘要、超標陰影、突升／突降偵測

- 「異常快速檢查」位於繪圖設定下方；先展開門檻設定，再檢查所選期間。各指標上下限與變化量留白即不檢查，不預設安全門檻。
- 摘要顯示超標區段、其中持續超標、突然上升、突然下降。點卡片可定位時段，定位切換原始資料並清除繪圖篩選與查詢子集；返回按鈕恢復檢查期間與原繪圖模式／尺度，不恢復已清除的篩選。
- 掃描使用所選期間與來源的原始資料，與繪圖數值篩選獨立。嚴格大於／小於；重複同值只算一次，衝突或缺值中斷判斷。資料中斷以各來源最大紀錄間隔設定判斷。
- 變化量與視窗內最早有效紀錄比較，缺值或過長間隔後重新開始。突變次數按命中的比較紀錄計，不等於獨立事件段數；外站每小時一筆時請將視窗設為至少 60 分鐘。
- 超標區段跨度只計最後與第一筆超標紀錄間隔，單點為 0；不是估計實際持續時間。橘色表示短暫、紅色表示達設定跨度的持續超標。陰影依原始紀錄，故平均線可能未超標。
- 陰影支援時間序列、合併、單日與降水量比較，並包含於 PNG；差值、每日疊圖、24 小時平均圖不套用。可關閉陰影後匯出正式圖表。
- 下載標記 CSV 包含所有事件、來源、時間、極值／變化量與判斷設定；網頁僅列每類前 100 項。新增設定可隨分析設定 JSON 儲存。
- 已用完整 166,824 筆內部資料測試掃描，並通過門檻邊界、缺值、重複、衝突、突變視窗、定位與 PNG 匯出測試。

- 手動點與最高最低標示會保留在 PNG；關閉自動挑選數值可只顯示指定重點。密集指定的文字可能重疊，請減少標示點或放大圖片。
- 編輯區改為標題、外觀、座標軸、下載四個折疊區，外觀改完即時預覽。
- 「每日疊圖」會逐日畫線，對齊一天中的時間；只有此模式顯示指標選擇。與把多天合併平均的 24 小時圖不同。

## 日期與平均方法

- CSV 保留原始文字，避免日期格式化造成時分秒遺失；Excel 保留原始日期值。
- 支援中文上午／下午、指定日期排列，以及獨立的日期與時分秒欄。欄位區顯示前三筆解析時間及解析失敗筆數；若全部為午夜會提示檢查欄位。
- 「CO₂ 24 小時平均圖」為獨立圖表模式，只在選取此模式後顯示。依所選期間與 CO₂ 數值篩選後的原始觀測，按 00–23 小時計算逐筆算術平均；不受每日／每小時彙整設定影響。這是觀測值加權平均，並非各天等權平均。
- 外站開關位於資料欄位區；關閉後重算且排除外站資料。
- 內外同指標使用相同顏色，外部使用粗虛線；圖例顯示線段而非填色矩形。
- CO₂ 24 小時平均已與實際原始 CSV 依時間欄另行計算的各小時平均逐項核對；每日／每小時彙整不影響結果。

## 功能

- 直接在瀏覽器讀取 `.xlsx`、`.xls`、`.csv`（資料不會上傳到伺服器）
- 支援一次上傳多個外部氣象站單日檔案並自動合併；CSV 可選擇 UTF-8、Big5／CP950 或自動偵測，避免繁中欄位亂碼
- 僅處理日期時間、溫度、相對濕度與 CO₂，並可手動指定欄位
- 自訂開始／結束時間，將 30 秒資料以 5 分鐘、15 分鐘、每小時或每日平均彙整
- 溫度、濕度、CO₂ 分為三張比較圖，蜂箱為實線、外部氣象站為虛線；可直接設定各指標顏色與座標軸標題
- 蜂箱與外部氣象站可各自指定日期格式，統一至同一時間軸；開始與結束時間預設為 SCD30 的第一與最後一筆紀錄
- 可對溫度、濕度、CO₂ 各自設定上下限篩選（含邊界），並選擇連續資料、逐日圖或三項合併圖；外部資料以同色粗虛線呈現
- 另提供 SCD30 CO₂ 的 24 小時平均圖，將所選區間內相同小時的觀測值平均
- 可下載目前圖表 PNG 與彙整後 CSV，便於研究可重現性紀錄

## GitHub Pages 部署

1. 建立新的 GitHub repository，將本資料夾所有檔案推送到 `main` 分支。
2. 在 repository 的 **Settings → Pages**，於 **Build and deployment** 選擇「Deploy from a branch」。
3. Branch 選擇 `main` 與 `/ (root)`，儲存後等待 GitHub 提供網址。

## 資料格式建議

每一列代表一個時間點；第一列為欄位名稱。至少需有一欄可解析的時間欄位，以及至少一個數值欄位。日期建議使用 `YYYY-MM-DD HH:mm:ss`，可避免不同電腦的地區日期格式誤讀。

> 論文或報告請記錄使用的時間範圍、彙整尺度、排除條件與氣象站位置／資料來源。網頁不會自動插補缺失資料。
